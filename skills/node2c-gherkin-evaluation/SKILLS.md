# Skill: Node 2C — Gherkin Scenarios Evaluation

## Identity
- **Name:** `node2c-gherkin-evaluation`
- **Type:** Evaluation Module (Skill)
- **Layer:** 2 — DAG Node 2C
- **Invoked by:** Layer 2 DAG Conductor after Node 2 completes

## Purpose
Validate Gherkin scenarios generated by Node 2 for correct format, completeness, and data-driven coverage. Rejects malformed scenarios and loops them back to Node 2 with fix instructions.

## Evaluation Rules

### 1. Gherkin Format Enforcement
- **Check:** Every scenario MUST follow the structure:
  ```gherkin
  Given X And Y
  When X And Y
  Then X And Y
  ```
- **Validation:**
  - Must start with `Given`
  - Must contain at least one `When`
  - Must contain at least one `Then`
  - `And` steps must follow a parent step (Given/When/Then)
  - No orphaned `And` or `But` steps
- **Action on fail:** REJECT with specific line-level fix instructions
- **Severity:** CRITICAL

### 2. Examples Table Validation
- **Check:** Scenario Outlines MUST include an `Examples` table
- **Validation:**
  - All `<placeholder>` variables in steps must appear in Examples header
  - Examples table must have at least 2 data rows
  - No empty cells in Examples table
- **Action on fail:** REJECT — "Missing or incomplete Examples table"
- **Severity:** CRITICAL

### 3. Scenario Coverage Check
- **Check:** Scenarios should cover:
  - At least one happy path
  - At least one negative/error case
  - Boundary conditions if applicable
- **Action on fail:** WARNING — "Missing negative test scenarios"
- **Severity:** WARNING

### 4. Tag Validation
- **Check:** Each scenario must have at least one tag from: `@smoke`, `@regression`, `@edge-case`, `@data-driven`
- **Check:** Feature must be tagged with story ID (e.g., `@PROJ-1234`)
- **Action on fail:** WARNING — "Missing classification tags"
- **Severity:** WARNING

### 5. Duplicate Detection
- **Check:** No duplicate scenario names within a feature
- **Check:** No semantically duplicate steps across scenarios
- **Action on fail:** REJECT — "Duplicate scenario detected"
- **Severity:** CRITICAL

## Input
- Gherkin `.feature` files from Node 2

## Output
```json
{
  "status": "APPROVED | REJECTED",
  "iteration": 1,
  "max_iterations": 3,
  "issues": [
    {
      "file": "checkout.feature",
      "line": 12,
      "rule": "gherkin-format",
      "severity": "CRITICAL",
      "message": "Missing 'When' step in scenario 'Submit order'",
      "fix_instruction": "Add a 'When' step between Given and Then blocks"
    }
  ],
  "approved_scenarios": 8,
  "rejected_scenarios": 2
}
```

## Iteration Loop
| Iteration | On Rejection | Action |
|-----------|-------------|--------|
| 1 | REJECTED | Return fix instructions → Node 2 regenerates |
| 2 | REJECTED | Return fix instructions → Node 2 regenerates |
| 3 | REJECTED | BLOCK pipeline — escalate to `#qa-alerts` for manual intervention |

## Downstream
- **On APPROVED** → Node 3 (Playwright Script Generation)
- **On REJECTED (iter < 3)** → Loop back to Node 2 with fix instructions
- **On REJECTED (iter = 3)** → Pipeline blocked, Slack alert
